# 교환 일지 (Exchange Diary)

GitHub API를 백엔드처럼 사용하는, 둘이서(추후 더 늘릴 수 있는) 쓰는 교환 일지 웹앱입니다.
별도 서버 없이 브라우저에서 GitHub Contents API를 직접 호출해서 글/댓글/이미지를 저장합니다.

이 문서는 **사이트를 설치·배포하는 사람**을 위한 문서예요. 같이 쓸 친구에게는 `사용법.md`를 보내주세요. 윈도우 컴퓨터로 설치한다면 `README-windows.md`를 참고하세요 (전체 과정이 다시 정리되어 있어요).

## 구조 한눈에 보기

- **사이트 코드** (이 프로젝트) → **공개(public) 레포**에 두고 GitHub Pages로 배포합니다. 개인정보가 전혀 없는 정적 웹앱이라 공개해도 괜찮아요.
- **일지 데이터**(글, 댓글, 이미지) → 둘만 볼 수 있는 **private 레포**에 저장합니다. 브라우저가 각자의 개인 액세스 토큰(PAT)으로 이 레포에 직접 읽고 씁니다.
- 토큰은 그 어떤 파일에도 커밋되지 않고, 사용하는 기기의 브라우저 `localStorage`에만 저장됩니다.
- 프로필 사진은 리사이즈된 작은 이미지로 `config.json` 안에 함께 저장됩니다(별도 파일 업로드 없음).

```
config.json                    멤버 목록(이름, 색상, 프로필 사진)
index.json                     날짜별 작성자 색인 (캘린더/피드 조회 속도용)
entries/2026-09-13/minji.json  민지의 9월 13일 일지 (본문, 기분, 체크리스트, 이미지, 반응, 댓글)
entries/2026-09-13/yohan.json  요한의 9월 13일 일지
images/2026-09-13/minji-...jpg 글/댓글에 첨부된 이미지
```

**꼭 알아두세요: 함께 쓰는 사람 모두가 각자 자기 GitHub 계정으로 토큰을 발급받아야 해요.** 토큰은 비밀번호와 같은 개념이라 절대 공유하면 안 되고, 발급받으려면 먼저 데이터 레포에 **협업자(Collaborator)로 초대**되어 있어야 해요. 이 흐름은 아래 1~3단계에 순서대로 정리되어 있습니다.

## 사이트 이름 바꾸기

배포하기 전에 이름을 바꾸고 싶다면 `src/config.js`의 `SITE_TITLE` 값만 바꾸면 돼요. 로고와 브라우저 탭 제목에 바로 반영됩니다.

같은 파일의 `DIARY_WORD` 값을 바꾸면, 화면 곳곳에 쓰이는 "일지"라는 단어(예: "OO의 일지", "아직 쓴 일지가 없어요")도 "일기" 등 원하는 말로 한 번에 바뀝니다.

## 1. Private 데이터 레포 만들기

1. GitHub에서 새 레포를 만드세요. (예: `our-diary-data`) → **Private**로 설정.
2. 아무 파일도 미리 만들 필요 없습니다. 앱을 처음 실행하면 자동으로 `config.json`, `index.json`을 생성해요.

## 2. 같이 쓸 사람을 협업자로 초대하기

Fine-grained 토큰은 **본인이 접근 권한을 가진 레포만** 선택할 수 있어요. 그래서 레포 소유자가 아닌 사람(예: 요한)이 이 private 레포에 쓰기를 하려면, 먼저 레포에 협업자로 초대되어 있어야 해요.

1. 레포 페이지 → **Settings** → 왼쪽 메뉴 **Collaborators** → **Add people**
2. 상대방의 GitHub 아이디 또는 가입한 이메일을 입력해서 초대를 보내세요.
3. 상대방은 GitHub에서 받은 초대 메일을 열거나, GitHub 우측 상단 종모양 알림 아이콘에서 초대를 확인하고 **수락(Accept invitation)**해야 해요. 수락 전에는 다음 단계에서 이 레포가 토큰 선택 목록에 나타나지 않아요.
4. 상대방이 둘 이상이라면(멤버가 3명 이상이 될 경우) 같은 방식으로 각자 초대하면 됩니다.

## 3. 개인 액세스 토큰(PAT) 발급 — 각자 자기 계정으로 1개씩

레포 소유자를 포함해서 **사용하는 모든 사람이 각자** 아래 과정을 자기 GitHub 계정에서 진행해야 해요. (2단계에서 초대받은 사람은 초대를 수락한 뒤에 진행하세요.)

**⚠️ 레포 소유자와 협업자는 발급 방식이 달라요.** GitHub의 Fine-grained 토큰은 아직 "내가 초대받아서 접근 권한만 있는 레포"는 선택할 수 없게 되어 있어요 (GitHub 자체의 알려진 제약이에요). 그래서:
- **레포 소유자** → Fine-grained 토큰 사용 (특정 레포 하나로 좁힐 수 있어서 더 안전함)
- **협업자로 초대받은 사람** → Classic 토큰 사용 (레포 하나로 좁히는 게 불가능하지만, 이 방법밖에 없어요)

### 레포 소유자

1. GitHub → 우측 상단 프로필 → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. **Repository access**: "Only select repositories" → 데이터 레포 선택
3. **Permissions** → Repository permissions → **Contents: Read and write**
4. 발급된 토큰(`github_pat_...`)을 복사해두세요. (한 번만 보여줍니다)
5. 만료 기한은 편의상 1년 정도로, 또는 무기한("No expiration")으로 설정해도 괜찮아요. 만료되면 설정 → 토큰에서 로그아웃 없이 바로 갱신할 수 있어요.

### 협업자로 초대받은 사람

Fine-grained 토큰 생성 화면에서 "Repository access"에 "Only select repositories" 옵션이 아예 안 보이고 "Public repositories"/"All repositories"만 있다면 정상이에요 — 협업자는 이 방식을 못 써요.

1. GitHub → 우측 상단 프로필 → **Settings** → **Developer settings** → **Personal access tokens** → 이번엔 **Tokens (classic)** 클릭
2. **Generate new token** → **Generate new token (classic)**
3. Note에 이름 적고, Expiration 설정
4. 체크박스에서 **`repo`** 하나만 체크 (Full control of private repositories — 하위 항목은 자동으로 다 체크됨)
5. 발급된 토큰(`ghp_...`)을 복사해두세요.

> 토큰 범위를 데이터 레포 하나로만 제한해두면(Fine-grained), 혹시 유출되더라도 다른 레포나 계정 전체에는 영향이 없어요. Classic 토큰은 이렇게 좁힐 수 없다는 게 GitHub의 한계라 어쩔 수 없어요. 어느 쪽이든 내 토큰을 상대방에게 알려주지 마세요 — 각자 자기 토큰만 자기 브라우저에 입력하면 됩니다.

## 4. 사이트 코드 준비 및 로컬 실행

### 터미널이 처음이라면 (cd 사용법)

터미널(맥은 "터미널" 앱, 윈도우는 PowerShell/명령 프롬프트)은 명령어를 입력해서 컴퓨터를 조작하는 화면이에요. 여기서 꼭 알아야 할 건 `cd` 명령 하나뿐이에요. `cd`는 "Change Directory"의 줄임말로, **지금 작업할 폴더로 이동하는 명령**이에요.

- `cd 폴더경로` — 그 폴더로 이동
- `cd ..` — 한 단계 위(부모) 폴더로 이동
- `pwd` — 지금 내가 어느 폴더에 있는지 확인 (Windows PowerShell에서도 동작해요)
- `ls` (윈도우는 `dir`) — 지금 폴더 안에 뭐가 있는지 목록 보기

아래 명령들(`npm install` 등)은 **반드시 이 프로젝트 폴더 안에서** 실행해야 해요. 다른 폴더에서 실행하면 "package.json을 찾을 수 없다"는 식의 에러가 나요. 가장 쉬운 방법은:

1. 압축을 푼 `exchange-diary` 폴더를 파일 탐색기(맥은 Finder)로 여세요.
2. 그 폴더 안 빈 공간에서 (맥) 마우스 오른쪽 클릭 → "새로운 터미널 탭에서 폴더 열기" 같은 메뉴가 있으면 바로 사용하세요. 없다면 터미널을 연 뒤 아래처럼 직접 경로를 입력하면 돼요.
   ```bash
   cd /Users/내이름/Desktop/exchange-diary
   ```
   (실제 경로는 압축을 푼 위치에 따라 달라요. Finder에서 폴더를 터미널 창으로 드래그하면 경로가 자동으로 입력돼서 편해요.)
3. `pwd`를 입력해서 경로 끝이 `exchange-diary`로 끝나는지 확인하세요.

### 설치 및 실행

```bash
npm install
npm run dev
```

터미널에 아래처럼 로컬 주소가 출력돼요:

```
VITE v5.4.0  ready in 320 ms
➜  Local:   http://localhost:5173/
```

이 `http://localhost:5173/` 주소를 복사해서 크롬/사파리 등 평소 쓰는 웹 브라우저 주소창에 붙여넣고 들어가면 사이트가 열립니다.

첫 화면에서 데이터 레포 정보(소유자/레포이름)와 토큰을 입력하게 됩니다.
처음 연결하는 사람(보통 레포 소유자)이 이름, 색상, (선택) 프로필 사진을 정하면 `config.json`이 만들어지고, 두 번째 사람은 같은 레포 + 자기 토큰으로 접속해서 "새 멤버로 참여하기"를 누르면 됩니다.

## 5. GitHub Pages로 배포하기

### 5-1. 공개 레포 만들고 코드 올리기 (git push)

1. GitHub에서 새 **공개(public)** 레포를 만드세요. (예: `our-diary`) — 이 레포에는 사이트 코드만 올라가고 개인정보는 없어요.
2. 이 프로젝트 폴더 안에서 터미널을 열고, 아직 git 저장소가 아니라면 아래를 순서대로 입력하세요.
   ```bash
   git init
   git add .
   git commit -m "first commit"
   git branch -M main
   git remote add origin https://github.com/<내아이디>/our-diary.git
   git push -u origin main
   ```
   - 이미 `git init`을 했다면 1~4번째 줄은 건너뛰어도 돼요.
   - `git remote add origin ...`이 "remote origin already exists" 에러를 내면, `add` 대신 `git remote set-url origin https://github.com/<내아이디>/our-diary.git`을 쓰세요.
   - `fatal: not a git repository`가 뜬다면 `git init`을 안 했거나 다른 폴더에서 명령어를 실행한 거예요. `pwd`로 지금 위치를 확인하고 프로젝트 폴더로 이동한 뒤 다시 시도하세요.

3. **`git push` 시 "Authentication failed"가 뜬다면**: GitHub는 더 이상 계정 비밀번호로 로그인하는 걸 지원하지 않아요. 아래처럼 **이 코드를 push하기 위한 용도의 Personal Access Token**을 따로 하나 발급받아야 해요. (일지 로그인용 토큰과는 별개예요!)
   1. GitHub → 프로필 → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
   2. **Repository access**: 방금 만든 사이트 코드 레포(`our-diary`) 선택
   3. **Permissions** → Repository permissions → **Contents: Read and write**
   4. 토큰을 생성하고 복사해두세요.
   5. `git push -u origin main`을 다시 실행하면 Username/Password를 물어봐요. **Username**엔 GitHub 아이디, **Password**엔 방금 만든 토큰을 그대로 붙여넣으세요. (화면에 글자가 안 보여도 정상입니다) 한 번 입력하면 이후엔 시스템에 저장되어 다시 안 물어봐요.
   6. 매번 토큰 다루는 게 번거롭다면 [GitHub Desktop](https://desktop.github.com)으로 로그인해서 push하는 방법도 있어요.

   > 이 토큰은 **코드를 올릴 때만** 쓰여요. 만료되거나 없어져도 이미 배포된 사이트나, 사용자들이 로그인할 때 쓰는 토큰(1~3단계에서 각자 발급받은 것)에는 전혀 영향이 없어요. 나중에 코드를 다시 push할 때만 새로 있으면 됩니다.

### 5-2. Vite 설정 및 배포 명령 실행

1. `vite.config.js`의 `base` 값을 레포 이름에 맞게 수정하세요.
   ```js
   base: '/our-diary/', // 레포 이름이 our-diary가 아니라면 바꿔주세요
   ```
2. 배포용 패키지가 이미 포함되어 있습니다:
   ```bash
   npm run deploy
   ```
   이 명령은 `npm run build` 후 `dist` 폴더를 `gh-pages` 브랜치로 올려줍니다. (내부적으로 git push와 같은 인증 과정을 거치므로, 5-1에서 인증이 이미 됐다면 추가 입력 없이 바로 됩니다)
3. 레포 Settings → Pages에서 소스를 `gh-pages` 브랜치로 지정하면 `https://<아이디>.github.io/our-diary/` 로 접속할 수 있어요. (처음 켤 땐 반영까지 1~2분 걸릴 수 있어요)
4. 배포된 주소를 같이 쓸 친구에게 알려주고, `사용법.md`를 함께 전달해주세요. (친구가 아직 협업자 초대를 수락하지 않았거나 토큰이 없다면, 2~3단계부터 안내해주세요.)
5. 코드를 나중에 수정하면, 그때마다 `npm run deploy`를 다시 실행해서 배포본을 최신 상태로 갱신하면 돼요.

## 6. 사이트 업데이트하는 방법

새 코드(예: 수정된 파일 전체가 든 zip)를 받았을 때 반영하는 순서예요.

1. **기존 프로젝트 폴더 내용을 새 파일로 덮어쓰세요.** 새로 받은 압축을 풀어서 기존 `exchange-diary` 폴더 위에 그대로 덮어씌우면 돼요. `node_modules` 폴더는 새 zip에 안 들어있으니 신경 쓰지 않아도 돼요.
   > ⚠️ 덮어쓰기 전에, `src/config.js`(사이트 이름)나 `vite.config.js`(`base` 경로)처럼 **직접 수정했던 값이 있다면 미리 메모**해두세요. 새로 받은 파일에는 그 값이 기본값으로 되어 있을 수 있어서, 덮어쓴 뒤 다시 적용해줘야 해요.
2. 프로젝트 폴더 안에서 혹시 모르니 한 번 더 설치해주세요.
   ```bash
   npm install
   ```
3. 배포하세요.
   ```bash
   npm run deploy
   ```
   이 명령이 알아서 `npm run build`로 최신 코드를 빌드하고 `gh-pages` 브랜치에 올려줘요. 1~2분 후 배포된 주소에 반영됩니다.

로컬에서 먼저 확인하고 싶다면 3번 전에 `npm run dev`로 미리 띄워보세요.

## 기능

- **일지 작성**: 오늘(또는 과거 아무 날짜나 자기 칸) 일지 작성/수정/삭제. 오늘의 기분(해시태그), 본문, 사진, 체크리스트 + 수면 시간 기록
- **체크리스트 커스터마이즈**: 기본은 약/외출·운동/청소/배달 주문이고, 설정에서 항목을 자유롭게 추가하거나 뺄 수 있어요. 이 설정은 **사람마다 따로** 적용돼요 (커스텀 반응·멤버 목록과 달리 공용이 아니에요).
- **반응**: 디스코드처럼 "+ 반응 추가" 버튼을 눌러 원하는 이모지를 골라 다는 방식. 이미지를 올려서 커스텀 반응(스티커)도 직접 만들 수 있어요.
- **댓글**: 텍스트 + 사진 첨부. 업로드 전에 자동으로 리사이즈해서 레포 용량을 아낍니다.
- **캘린더 보기**(기본 화면): 위쪽 달력에서 날짜를 고르면 그 아래에 두 사람의 그날 일지가 나란히 떠요.
- **모아보기**: 사이드바에서 멤버 프로필을 누르면 그 사람 글만 최신순으로 모아볼 수 있어요. 같은 프로필을 다시 누르거나 "홈"을 누르면 캘린더로 돌아갑니다.
- **멤버 추가/삭제**: 설정에서 언제든 새 멤버를 추가하거나, 더 이상 쓰지 않는 멤버를 삭제할 수 있어요. (멤버를 삭제해도 그 사람이 이미 쓴 글은 남아있어요)
- **프로필**: 각자 설정에서 프로필 사진(직접 자르기 가능)과 테마 색·배경색을 정해서 적용할 수 있어요.
